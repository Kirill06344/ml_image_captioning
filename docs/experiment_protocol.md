# Протокол и выполненная оценка

## Данные

Рабочая трактовка задания — 5000 изображений всего: 4000 train из train2014 и по 500 val/test
из val2014. Это допущение по формулировке, принятое до загрузки; стандартным Karpathy test 5k
такое разбиение не является. Фактическое число подписей — 20010/2500/2500.
Отбор фиксирован сортировкой SHA-256 от image_id, без подбора seed по качеству.
Все подписи одной фотографии остаются вместе. Manifest содержит SHA-256 JSONL, аннотаций и изображений.
Словарь и частоты строятся только по train. Единица оценки и bootstrap — изображение.

## Модель и независимость

Кодировщик — torchvision ResNet18, ResNet18_Weights.IMAGENET1K_V1,
файл resnet18-f37072fd.pth. Источник:
[карточка весов torchvision 0.21](https://docs.pytorch.org/vision/0.21/models/generated/torchvision.models.resnet18.html).
Документировано классификационное предобучение ImageNet-1K, а не COCO captioning.
Отсутствие всех совпадений изображений между исходными корпусами отдельно не доказано.
Готовые COCO-captioners не используются как независимый test-ориентир.

RGB → resize 256 / center crop 224 → нормализация ImageNet → карта 49 × 512.
Кодировщик и BatchNorm заморожены. Проекция 512→256, обучаемые позиции 49 ячеек;
декодер с нуля: 2 Transformer-слоя, 4 головы, FFN 1024, dropout 0.1, d=256.
Максимум 32 токена вместе с BOS/EOS. Словарь lowercase regexp, min_count=2,
фактически 3824 токена. Токенизация модели отличается от PTB-токенизации метрик.
PAD=0 исключается из cross entropy; причинная маска скрывает будущие слова.

## Предварительно выбранный рецепт

Seed=1; FP32; AdamW, lr=0.0003, weight_decay=0.01; постоянный lr; batch=32;
gradient clipping=1.0; максимум 10 эпох; patience=3 по val CIDEr. Аугментаций нет.
Все 20010 train-подписей используются, 626 обновлений/эпоху.
После каждой эпохи — greedy val (beams=1), сохранение наибольшего CIDEr; при равенстве остаётся первый.
Checkpoint включает encoder/decoder, vocabulary, архитектуру, fingerprint, run и параметры генерации.
После восстановления лучшего checkpoint считаются все val-метрики.

Постоянная подпись — наиболее частая нормализованная подпись train, при равенстве лексикографический порядок.
Retrieval — cosine между L2-нормированными средними ImageNet-признаками; возвращается первая
исходная подпись ближайшего train-изображения. Held references в поиске не участвуют.

Предварительно обсуждалась гипотеза снижения переобучения одним слоем. По указанию пользователя
до её запуска оставлен **один** полноценный обучающий рецепт caption-control. Caption-one-layer не запускался;
выводов об оптимальности глубины по сравнению рецептов не делается. Это изменение объёма работы,
а не отбор удачного рецепта по test. Бейзлайны зафиксированы до итоговой оценки.

## Метрики

pycocoevalcap==1.2, [репозиторий](https://github.com/salaniz/pycocoevalcap).
Stanford PTBTokenizer 3.4.1, lowercase, удаление COCO-пунктуации.
Java METEOR 1.5 с user.language=en, user.country=US и LC_ALL=C.UTF-8;
иначе русская локаль воспроизводимо вызывает InputMismatchException в Java Scanner.
Формулы и SCORE/EVAL-протокол библиотеки не изменены, JVM-локаль включена в scorer metadata.
SPICE не используется.

Главная метрика — Cider(n=4,sigma=6), корпусный IDF по оцениваемому split,
clipping и Gaussian length penalty (семейство CIDEr-D). Сохраняется непосредственный вывод
библиотеки, включая внутренний множитель 10; внешнего ×100 нет. CIDEr не ограничен [0,1].
Дополнительные — BLEU-1/2/3/4 (корпусные), METEOR, ROUGE-L, все raw.
Имена, токенизация и шкалы у сравниваемых строк идентичны. Числа публикаций с другими
выборками, IDF и масштабами напрямую не сопоставляются.

Рабочий практически заметный прирост CIDEr был задан как 0.02 raw, это не универсальный порог.
Парный bootstrap по image_id с фиксированными IDF полного split — 10000 повторов, seed=1.
Интервал условен на корпусе и checkpoint, не оценивает разброс повторного обучения.
Один обучающий seed не позволяет оценить устойчивость рецепта по seeds.

## Порядок выбора и test

Выбор checkpoint по val; collect_results.py фиксирует selection.json до test.
Reference-ориентиры не могут победить как candidate. На test допускаются только выбранная
модель и зафиксированные val-бейзлайны, с той же генерацией. Дубли и неполные image_id,
изменённые эталоны, другой fingerprint/scorer/units блокируют оценку/сравнение.

Фактически лучший checkpoint — 5-я эпоха, val CIDEr 0.6658330.
После 8-й эпохи сработала ранняя остановка, всего 5008 обновлений. Выбор сохранён до test.
Test оценён без дообучения: CIDEr модели 0.6390188, retrieval 0.3845964, constant 0.0649123.
Все метрики берутся из runs/*/scores_val/test.json через tools/collect_results.py.
Bootstrap разности test CIDEr к retrieval: 0.2544224, интервал [0.2043475; 0.3041602].

## Проверки и ресурсы

Локальные synthetic/COCO smoke, затем GPU smoke caption-smoke-main (16/16 изображений,
10 обновлений) подтвердили finite loss/градиенты, checkpoint/reload и полный scorer.
GPU smoke: Tesla T4, 25.99 с по таймеру тренера, peak allocated PyTorch 197.56 МиБ.
Его малый словарь 117 и batch=4 не использовались для обещания времени полного опыта.

Основной caption-control на badzhik завершён: 486.1 с (0.135 часа по таймеру тренера),
без очереди и установки окружения. Peak allocated PyTorch — 286.13 МиБ, без полного контекста CUDA.
Код использовал cuda:0; число всех выделенных устройств из этого показателя не определяется.
Перед запуском проверялись аккаунт и свободная квота с учётом резерва. Предельное время ядра —
7200 секунд через CLI --timeout, также ограничены эпохи и early stopping. Предел не достигнут.

Обучение/val: torch 2.11.0+cu128, torchvision 0.26.0+cu128 на Kaggle.
Test: torch 2.6.0+cpu, torchvision 0.21.0+cpu локально; scorer везде pycocoevalcap 1.2.
Checkpoint успешно восстановлен в CPU-окружении. Test и оба бейзлайна не потребовали нового GPU-обучения.
Версии и параметры сохранены в run.json/evaluation_test.json. Все 3000 прогнозов проверены.
Полный pytest — 71 passed.

Код идёт приватным датасетом, src хэшируется. При queued или неизвестном статусе ожидаемую
версию кода не обновлять и обучение не отправлять повторно. Журнал попытки пишется до push,
состояние submitted — после подтверждения. --submit-only завершает терминальную команду после отправки;
--fetch-only только получает существующие результаты. Новый remote и push в git не выполнялись.
